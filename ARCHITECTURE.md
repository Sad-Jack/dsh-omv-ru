# Структура проекта

`dsh-omv` — плагин DSH с серверной и браузерной частями. Node-хост подключает рабочую область `oh-my-vul` к Cordis; браузерная часть отображает панель аудита в штатных сеансах, боковой панели и настройках DSH.

## Каталоги

```text
.
├── src/
│   ├── index.ts              # Хост: Cordis, Service, HTTP, Tools, Commands
│   ├── contracts.ts          # Общие типы протокола хоста/клиента
│   ├── client/
│   │   ├── index.tsx         # Клиент: DSH slots, сеанс, выбор страниц
│   │   ├── pages.tsx         # Обзор, находки, качество, воспроизведение, кампании, поиск
│   │   ├── ui.tsx            # Компоненты Hero, Metric, Status, Modal, Icon
│   │   ├── runtime.ts        # HTTP/SSE, разбор ответов, форматы и состояния
│   │   ├── types.ts          # Инъекции клиента, Tab, Icon, константы команд
│   │   └── styles.ts         # Визуальные стили через DSH alias
│   ├── workbench.ts          # Агрегация рабочей области и маршрутизация действий
│   ├── workbench/quality.ts  # Очередь и сигналы качества
│   └── *.ts                  # Сервисы Workflow, Runner, Dedup, Report и др.
├── tests/                    # Модульные/интеграционные Vitest отдельно от исходников
├── contracts/                # Снимки внешних API-контрактов
├── ARCHITECTURE.md           # Структура и границы модулей
├── DSH-INTEGRATION.md        # Правила DSH и соответствие реализации
├── omv-audit-desk-overview.png # Иллюстрация README
├── cordis.patch.yml          # Установочные настройки профиля DSH
└── package.json              # Манифест обеих частей и точка сборки
```

## Границы модулей

### Хост

- `src/index.ts`: жизненный цикл и регистрация точек интеграции, без прикладных правил.
- `src/workbench.ts`: объединение моделей для чтения, маршрутизация действий и область рабочей среды.
- `src/workbench/quality.ts`: порядок очереди, сигналы качества и представление отчётов/проверок; производные правила вынесены из входного агрегатора.
- Для каждого длительного процесса — Campaign, воспроизведения, совместной работы, дедупликации, отчёта — отдельный сервис. Хранение остаётся в `.omv` и схеме `oh-my-vul`.

### Клиент

- `client/index.tsx`: интеграция DSH, обновления/события, действия с сеансом и выбор страницы.
- `client/pages.tsx`: представление отдельных страниц; общее состояние передаётся наверх через props.
- `client/ui.tsx`: отображаемые компоненты без прикладных побочных действий, чтобы не дублировать состояния, пустые экраны и окна.
- `client/runtime.ts`: API, время, подписи состояний и цвета. Страницы не собирают URL и не разбирают ответы самостоятельно.
- `client/styles.ts`: фон, границы, шрифты и цвета состояния через DSH alias. Новые визуальные правила сначала выражать через токены хоста.
- `tests/`: импорты производственных модулей только из `../src`; Vitest собирает тесты через `vitest.config.ts`, отдельная проверка типов — `tsconfig.tests.json`.

## Правила изменений

1. Для новой возможности DSH сначала обновить `inject`, slot или host service, затем добавить кнопку.
2. Новое поле API сначала добавить в `contracts.ts` и снимки `contracts/`, затем подключать к хосту/клиенту.
3. Компоненты страниц получают данные; не читают `.omv` напрямую.
4. Генерируемые материалы — `lib/`, `*.tgz`, журналы Playwright, варианты снимков, локальная `.omv` — не включать в Git.
5. Перед коммитом выполнить `npm run check`; визуальные изменения проверить хотя бы в одном Web profile DSH. Это правила разработки исходного проекта; русификация не запускает приложение автоматически.
